# WinHomeDesk 0.3.3-local — 모니터별 개별 연결 / H.264

Windows용 로컬 개발판입니다. 기존 0.3.1의 전체 화면 공유에 모니터별 개별 연결을 추가했습니다. Mac 엔진에 의존하지 않습니다. 0.3.3 소스 스냅샷을 GitHub에 공개합니다. 기존 실행 ZIP의 릴리스 등록과는 별도입니다.


## 0.3.3 수정 사항

- 환경 설정: 예약 작업이 없을 때의 HRESULT `0x80070002`가 .NET에서 `FileNotFoundException`으로 변환되는 경우도 처리합니다. 기존 코드는 `COMException`만 처리해 창이 열리지 않았습니다. 작업 조회에서만 없음을 처리하며 접근 거부나 DLL/COM 초기화 오류는 숨기지 않습니다.
- 서버 커서 깜빡임 대응: 캡처 프레임과 마우스 이벤트마다 실행하던 `EnumDisplaySettingsEx` 호출을 시작 시점으로 제한했습니다. 실행 중 배치 확인은 USER32 좌표 조회와 보이지 않는 `WM_DISPLAYCHANGE` 수신 창으로 처리합니다. 화면 변경 시 서버를 중지하는 동작은 유지합니다.
- GDI 캡처에서 `CAPTUREBLT`를 제거하고 `SRCCOPY`를 사용합니다. GDI에서 일부 레이어/투명 창의 표시가 달라질 수 있으므로 해당 화면이 누락된다면 DirectX 자동 모드를 사용하세요. 이 변경은 H.264를 비활성화하지 않습니다.
- 같은 오류를 주입한 설정 창 열기, 기존 자동 시작 등록/복원 모의 시험, 디스플레이 설정 조회 없이 200회 배치 확인, 화면 변경 이벤트에 따른 중지 시험을 통과했습니다. 실제 디스플레이 변경이나 마우스 이동은 테스트에서 수행하지 않았습니다.
- 실제 커서 깜빡임이 사용자의 장치에서 사라졌는지는 새 버전 실행 후 확인이 필요합니다. 모니터/그래픽 드라이버별 차이까지 확인한 것은 아닙니다.


## 설치와 개별 창 연결

1. 기존 앱의 트레이 메뉴에서 **종료 (서버도 종료)**를 선택합니다. 창의 X는 트레이로 숨기기입니다.
2. 새 ZIP 전체를 **새 폴더**에 압축 해제하고 `WinHomeDesk.exe`를 실행합니다. 기존 버전의 EXE/DLL을 섞지 마세요.
3. Windows 디스플레이 설정을 **확장**으로 설정합니다.
4. **공유 모니터 → 모니터별 개별 연결 (RDCMan)**을 선택합니다. 다른 PC에서 접속할 수 있는 서버 주소와 시작 포트를 지정합니다.
5. 전송 방식은 **자동 — H.264 AVC420 우선** 또는 **H.264 AVC420**을 사용합니다. 공유 동의란을 선택하고 **서버 시작**을 누릅니다.
6. **모니터 RDG 저장**을 누르거나 **RDCMan 그룹 관리**에서 자동으로 채워진 모니터 목록을 저장합니다.
7. 관리 PC의 RDCMan **2.93 또는 3.22**에서 RDG를 엽니다. `PC이름 — DISPLAY1`, `PC이름 — DISPLAY2` 등의 항목이 생성됩니다. 각 연결은 사용자 `surface`, Domain 빈칸, **WinHomeDesk 앱 전용 암호**를 사용합니다. RDG에 암호는 저장하지 않습니다. 필요하면 Shift+Enter(Connect As)로 입력합니다.
8. 각 항목에 접속한 뒤 해당 항목의 우클릭 메뉴에서 **Undock**을 선택합니다. 모니터마다 별도 창을 배치할 수 있습니다. 새 RDG는 창 크기에 맞춰 화면을 축소하도록 설정합니다.

예를 들어 시작 포트가 **3390**이고 화면이 3개면 각각 **3390, 3391, 3392**로 접속합니다. 서버 방화벽 및 사용 중인 VPN/포트 전달 설정에서도 실제 사용할 TCP 포트를 모두 허용해야 합니다. 프로그램이 방화벽 규칙을 자동으로 바꾸지는 않습니다.

각 창은 **같은 로그인 세션의 물리 화면**을 보여줍니다. 독립 사용자 세션이나 별도 마우스 포인터를 만들지 않습니다. 키보드 포커스와 마우스는 공유됩니다. Windows 모니터 복제 설정에서는 같은 화면이 보일 수 있습니다. DISPLAY 번호는 엔진의 장치 식별자이며 Windows 설정 앱의 표시 번호와 같다고 보장하지 않습니다. 연결한 화면과 로그의 장치/좌표를 확인하세요.

## 동작과 설정

- **주 모니터만 공유 / 모든 모니터 공유 / 모니터별 개별 연결** 중 선택합니다. 전체 공유는 기존처럼 한 연결창에 합친 화면을 표시합니다. 실행 중에는 범위를 바꿀 수 없습니다.
- 개별 모드는 모니터마다 별도 엔진을 실행하고 시작 포트부터 연속 배정합니다. 각 포트는 인증된 연결 1개를 받습니다. 범위가 65535를 넘으면 시작을 거부합니다.
- 모니터 장치 이름으로 캡처 대상을 고정하며, 없는 장치를 요청하면 전체 화면을 대신 노출하지 않고 실패합니다. 세로 화면과 음수 원점도 각 창의 좌표에 맞게 변환합니다.
- 소리는 **첫 번째 항목**에서만 전송합니다. 그 창을 연결하지 않으면 소리를 들을 수 없습니다. 실시간 성능/코덱 요약도 첫 번째 연결 기준이며 다른 모니터의 세부 로그에는 장치·포트 표식을 붙입니다.
- **인증서 지문 확인**은 실행 중인 각 모니터 포트의 지문을 표시합니다. 각 포트는 별도 인증서 저장 폴더를 사용합니다. 최초 연결 시 해당 포트의 지문과 비교하세요.
- X로 창을 닫아도 모든 서버가 트레이에서 유지됩니다. **서버 중지**, 트레이 **종료**, 한 엔진의 실패/종료 시 함께 정리합니다. 시작 후 30초 안에 모든 포트가 준비되지 않으면 전체를 중지합니다.
- 모니터 추가/제거·배치/회전/해상도 변경 또는 잠금/보안 데스크톱 전환 뒤에는 서버를 다시 시작하세요. 장치나 포트 배정이 달라졌다면 RDG도 다시 만드세요.
- 공유 모드 선택은 저장되며 자동 서버 시작에도 적용됩니다. 새 실행 경로로 자동 시작하려면 새 앱의 **환경 설정**에서 자동 시작 옵션을 다시 저장하세요. 기존 설정/DPAPI 암호 보호와 관리자 자동 시작 방식은 유지합니다.
- 개별 모드에서 **연결 파일 저장** 버튼은 **모니터 RDG 저장**으로 바뀝니다. 기존 단일/전체 모드의 RDP 파일 저장 기능은 유지합니다.

## 화질과 성능

H.264는 각 모니터를 별도로 인코딩합니다. DXGI 캡처가 실패하면 GDI, GPU 인코더가 실패하면 CPU H.264로 전환합니다. 여러 창에 동시에 접속하면 인코더와 네트워크 부하가 늘어납니다. 속도가 부족하면 1440 화질 또는 낮은 FPS를 선택하세요.

개별 모드는 모니터별로 1920/1440 화질 상한을 적용합니다. 전체 공유는 모니터 배치를 유지하는 공통 배율을 사용합니다. 두 모드 모두 인코딩 캔버스당 최대 변 8192 및 16픽셀 패딩 후 9,437,184픽셀 한도가 적용됩니다. 원본 우선도 이 한도 안에서 동작합니다.

## 검증 범위

- Windows 엔진/DLL/GUI 재빌드 및 기존 0.3.1 주/전체 공유 회귀 시험 통과.
- 실제 가로 2개·세로 1개 모니터에 **동시 3개 연결**. 기존 Microsoft RDP ActiveX 엔진 및 RDCMan 3.22의 RDCore 엔진 각각 NLA 인증과 H.264 AVC420 전송 확인. 1440 품질에서 가로 1440×808 두 개, 세로 808×1440 한 개를 별도 전송했습니다. 새 엔진의 화면 이미지에서도 서로 다른 화면과 세로 배치를 확인했습니다.
- 물리 장치 선택, 없는 장치 거부, 음수 좌표와 모서리/중앙 입력 좌표, 포트 상한, RDG 내보내기·가져오기, 동일 PC의 여러 포트, 모드 저장 및 언어 전환 시험 통과.
- 테스트용 로컬 자식 프로세스로 동시 시작, X로 숨기기, 전체 중지, 포트 충돌, 한 엔진의 예기치 않은 종료, 앱 종료 시 정리 확인.
- 기존 암호 보호·트레이·자동 시작 모의 시험 통과. 실제 작업 스케줄러 등록 시험은 환경 접근 제한으로 생략했습니다.
- 이번 실제 영상 시험은 GDI + CPU H.264를 사용했습니다. GPU 성능, 장시간 원격 사용, 오디오 싱크, 실제 모니터 분리, 사용자 마우스 위치 일치는 별도 확인이 필요합니다. 사용 중인 마우스에 간섭하지 않도록 이번에는 실제 입력 주입 시험을 하지 않았습니다. RDCMan 전체 UI의 장시간 운용 대신 각 버전의 RDP 엔진으로 접속을 검증했습니다.

빌드: `work/Build.ps1`. 테스트: `test029.py`, `test030.py`, `test031.py`, `test032.py`, `test_rdg031.ps1`. `test031.py`는 `--engine`, `--compiler`, `test032.py`는 `--compiler` 경로를 받습니다. 패키징: `work/package032.py --base <0.3.0 런타임 ZIP> --output <빈 출력 폴더>`.

문제가 있으면 새 앱을 트레이에서 종료하고 기존 설치를 다시 실행합니다. 이 작업에서는 기존 설치와 실제 시작 프로그램 등록을 변경하지 않았습니다.
