# WinHomeDesk 0.3.7-local — 복사·붙여넣기

**2026-11-03 사용자 확인:** 0.3.7 적용 후 RDCMan 2.93에서 텍스트와 파일 붙여넣기가 정상 작동한다고 확인했습니다. 다른 클라이언트/환경 전체의 호환성을 보증하는 결과는 아닙니다.

이 패키지는 Windows용 실험 버전입니다. 기존 멀티 모니터/H.264 기능에 RDP 클립보드 채널을 추가했습니다.

## 0.3.7 파일 응답 대기 및 잠금

0.3.6의 RDCMan 2.93 로그에서 파일 목록과 크기(5,726바이트)는 정상이며, 첫 내용 요청을 보낸 후 15초 동안 응답을 받지 못한 것이 확인됐습니다. 0.3.6의 크기 조회 수정은 이 사례의 원인이 아니었습니다. 아래 변경은 수신 호환성을 보완하지만, 이후 사용자가 성공을 확인했습니다(위 확인 기록 참고).

- 상대가 잠금을 지원하면 파일 목록을 요청하기 전에 Lock Clipboard Data를 보내고, 이후 내용/크기 요청에 같은 clipDataId를 포함합니다. 데이터 객체와 스트림이 모두 해제되면 Unlock을 보냅니다. 잠금을 지원하지 않는 상대는 기존 요청 방식을 유지합니다.
- Windows STA에서 파일 응답을 기다리는 동안 COM 호출을 처리하도록 CoWaitForMultipleHandles를 사용합니다. 시간 제한과 연결 종료 취소는 유지합니다.
- 늦게 도착하거나 식별자가 일치하지 않는 파일 응답을 로그에 남깁니다.
- 자동 시험은 실제 COM 아파트 간 호출, 잠금 수명, 구형 협상 방식, 실제 DLL 패킷 생성/해석과 기존 텍스트/파일 회귀 시험을 포함합니다. 두 PC 간 Explorer 붙여넣기를 자동 시험한 것은 아닙니다.

기존 연결을 완전히 끊고 새 서버로 재접속한 뒤 접속 PC에서 파일을 새로 복사하세요. 계속 실패하면 로그 저장 파일을 보내주세요. 파일명이나 파일 내용은 로그에 넣지 않습니다.

## 0.3.6 파일 수신 호환 수정

0.3.5에서 텍스트 수신은 정상이라는 사용자 확인을 받았으나 파일 붙여넣기는 읽기 오류가 보고되었습니다. 코드 검사에서 파일 목록에 크기가 없는 경우를 거부하던 문제를 수정했습니다. 이 문제가 해당 PC의 오류 원인인지 확인하려면 재시험이 필요합니다.

- 파일 크기가 목록에 없으면 RDP FILECONTENTS_SIZE 요청으로 64비트 크기를 조회한 뒤 내용을 읽습니다.
- 파일 속성의 유효 표시를 확인해 폴더/파일을 구분하며, 폴더의 빈 스트림 요청도 처리합니다.
- 크기 조회 오류, 상대 PC의 읽기 거절, 시간 초과와 중간 내용 누락을 로그로 구분합니다. 파일명과 내용은 기록하지 않습니다.
- 자동 시험: 크기 생략/알려진 크기, 빈 파일/폴더, 여러 조각의 바이트 일치, 4 GiB 초과 위치, 잘못된 응답 및 실제 DLL의 패킷 생성/해석.

실제 두 PC 사이 파일 붙여넣기 성공은 아직 확인되지 않았습니다. 계속 실패하면 작은 일반 `.txt` 파일을 새로 복사해 시험한 직후 **로그 저장**으로 생성한 파일을 확인하세요. `file-request`, `file-response-rejected`, `file-read-failed` 기록으로 실패 지점을 구분할 수 있습니다.

## 0.3.5 수신 경로 수정

0.3.4에서 접속 PC → 서버 방향의 요청이 시간 초과된 후 후속 텍스트 수신까지 차단되는 현상을 보완했습니다. 최초 시간 초과의 원인은 기존 로그만으로 확정할 수 없습니다.

- 연결 직후 기존 서버 클립보드를 자동 송신해 접속 PC의 최초 복사 내용을 덮는 경합을 제거했습니다.
- 텍스트와 파일 목록을 먼저 수신·검증한 뒤 게시합니다. Windows 앱의 붙여넣기 콜백에서는 이미 받은 데이터를 즉시 반환합니다. 파일 내용은 붙여넣을 때 계속 분할 전송합니다.
- 수신 게시 중 변경 알림이 반대 방향으로 재전송되는 것을 막고, 수신 도중 사용자가 새로 복사한 내용은 덮어쓰지 않습니다.
- 파일 조각의 시간 초과는 이후 텍스트 요청을 차단하지 않습니다. 식별자가 없는 형식 응답은 늦은 응답을 소비한 뒤 새 요청을 허용하며, 상대가 계속 무응답이면 재접속해야 합니다.
- Explorer의 FileContents 형식 조회(`lindex=-1`)를 허용하고 실제 파일 읽기의 인덱스는 따로 검사합니다.
- 로그에 요청 형식·전송 결과·수신 바이트 수·게시 성공 여부를 추가했습니다. 본문이나 파일명은 기록하지 않습니다.

업데이트 후 기존 연결을 끊고 다시 접속한 다음 **접속 PC에서 다시 복사**해 시험하세요. 이번 자동 시험은 DLL의 실제 패킷 생성/분할 응답 처리와 위 회귀 시나리오를 포함하지만, 사용자 두 PC 사이의 최종 재시험은 아직 필요합니다.

## 업데이트와 사용

1. 기존 WinHomeDesk를 트레이 메뉴의 **종료 (서버도 종료)**로 완전히 닫습니다.
2. 새 Windows x64 ZIP **전체**를 풉니다. EXE만 교체하면 안 됩니다. 자동 시작을 사용했다면 기존 설치 폴더의 파일을 교체하거나, 새 경로에서 환경 설정을 다시 저장하세요.
3. 새 `WinHomeDesk.exe`를 실행합니다. 환경 설정의 **텍스트·파일 복사/붙여넣기 허용**은 기본 켜짐입니다. 변경 사항은 서버를 재시작해야 적용됩니다.
4. 서버를 시작하고 **연결 파일 저장 / RDCMan 그룹 관리**에서 RDP 또는 RDG를 새로 만듭니다.
5. 접속 PC에서 다시 연결합니다. 메모장 텍스트나 파일 탐색기의 파일·폴더를 `Ctrl+C`로 복사하고 반대쪽 PC에서 `Ctrl+V`로 붙여넣습니다. 두 방향 모두 같은 방식입니다.

이전 연결 파일은 클립보드가 꺼져 있을 수 있습니다. RDP 파일에서는 `redirectclipboard:i:1`, RDCMan에서는 해당 서버의 **Properties → Local Resources → Clipboard**를 켠 뒤 연결을 끊고 다시 접속하세요. 상위 그룹 설정을 상속한다면 해당 그룹의 설정도 확인하세요. 새로 생성한 RDG에는 서버별로 클립보드 사용 설정이 들어갑니다. 드라이브 전체를 공유할 필요는 없습니다.

**모니터별 개별 연결:** 첫 번째 모니터(기본 포트)의 연결을 유지해야 합니다. 그 연결이 클립보드 교환을 담당하고, Windows 클립보드는 모든 모니터에서 함께 사용합니다. 첫 번째 연결을 종료하면 나머지 화면만으로는 클립보드를 교환하지 않습니다.

## 지원 범위

- 한글·영문·줄바꿈·이모지를 포함한 일반 Unicode 텍스트.
- 파일 탐색기에서 복사한 일반 파일, 여러 파일, 하위 폴더, 빈 파일.
- 파일은 붙여넣기 시 부분 전송합니다. 파일 전체를 메모리에 올리거나 수신용 임시 폴더에 미리 저장하지 않습니다.
- **복사**만 지원합니다. 잘라내기를 하더라도 반대편 붙여넣기로 원본을 자동 삭제하지 않습니다.
- 그림, HTML/RTF 서식, Outlook 첨부파일 같은 가상 파일, 정션·심볼릭 링크, OneDrive 온라인 전용 파일은 이번 버전의 지원 범위에 포함하지 않습니다. 클라우드 파일은 먼저 로컬에 다운로드하세요.
- 텍스트 약 16MiB, 파일 목록 4,096개, 폴더 깊이 32단계, 상대 파일 이름 259자 한도입니다. 동일 이름의 최상위 항목이나 접근할 수 없는 파일이 있으면 파일 목록 전체를 보내지 않습니다.
- 전송 중 다른 내용을 복사하거나 연결이 끊기면 붙여넣기가 실패할 수 있습니다. 완료 전에는 원본을 유지하세요. 상대 PC의 각 데이터 응답은 최대 15초 기다립니다. 파일 조각 요청은 실패 후 다른 전송을 시도할 수 있습니다. 형식 응답이 늦게 도착하면 이를 폐기한 후 다시 복사할 수 있고, 끝내 도착하지 않으면 재접속이 필요합니다.
- 소스 파일을 복사한 동안 읽기 전용 핸들로 유지하므로 수정/삭제가 잠시 제한될 수 있습니다. 다른 내용을 복사하거나 접속을 종료하면 해제됩니다.

## 확인된 범위와 남은 확인

자동 시험: Unicode 텍스트 요청/응답, 실제 IDataObject/IStream 호출, 한글 이름·폴더·빈 파일, 1MiB 이상의 분할 읽기, EOF, 가상 64비트 오프셋, 전송 목록 잠금/해제, 잘못된 경로·이전 데이터 거부, 진행 중 붙여넣기의 연결 종료 취소, 숨은 클립보드 창의 시작/종료를 확인했습니다. 기존 설정·번역·모니터별 프로세스 및 커서 관련 회귀 시험도 수행했습니다. RDCMan 3.22의 실제 설정 파서가 생성된 RDG의 Clipboard 활성화 설정을 받아들이는 것도 확인했습니다.

이 개발 환경에서는 별도 Windows 윈도 스테이션 생성이 접근 거부되어 실제 OS 클립보드 변경 시험을 건너뛰었습니다. 사용 중인 클립보드는 읽거나 덮어쓰지 않았습니다. **RDCMan 2.93/3.22 또는 mstsc로 서로 다른 두 PC에서 텍스트·파일을 실제 붙여넣는 최종 호환성 시험은 아직 완료하지 않았습니다.** 4GiB 초과 실제 파일 전송 또한 미검증입니다.

문제가 있으면 새로 연결한 뒤 텍스트 한 줄과 작은 파일 하나로 먼저 확인하고 WinHomeDesk의 로그를 저장하세요. `CLIPBOARD ready`, `local`, `remote`, `client-disabled`, `request-timeout`을 확인할 수 있습니다. 클립보드 본문, 파일 내용, 파일 이름은 새 진단 로그에 남기지 않습니다.
