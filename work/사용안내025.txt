WinHomeDesk 0.2.5 — 오른쪽 Alt로 전달되는 한영키 수정

이번 변경
- 환경 설정에 '오른쪽 Alt를 한영키로 사용'을 추가했습니다. 기본값은 켜짐입니다.
- 이전 버전은 원격 전경 창의 키보드 배치와 MapVirtualKey 결과가 모두 한영키를 가리킬 때만 변환했습니다.
  이번 옵션을 켜면 해당 판별에 관계없이 RDP의 오른쪽 Alt(E0 38)를 한영 전환 키로 전달합니다.
- 누름/뗌을 한 쌍으로 보내고 반복 입력과 짝이 되는 뗌은 무시해 두 번 전환되는 현상을 방지합니다.
- 왼쪽 Alt와 일반 키는 바꾸지 않습니다. 일반 오른쪽 Alt/AltGr가 필요하면 옵션을 해제하세요.
- INPUT_ALT에 오른쪽 Alt 수신, 설정, 원격/클라이언트 배치와 처리 결과를 기록합니다.
  INPUT_IME에는 한영키 변환 후 Windows 입력 API에 전달한 결과를 기록합니다. 일반 문자/암호는 기록하지 않습니다.
- 기존 설정 파일에 새 항목이 없으면 기본 켜짐으로 읽습니다. 계정·암호·인증서·RDP/RDG 파일은 유지됩니다.

업데이트
1. 기존 WinHomeDesk를 트레이 메뉴의 '종료 (서버도 종료)'로 완전히 종료합니다.
2. 새 ZIP 전체를 새 폴더에 풀고 WinHomeDesk.exe를 실행합니다. EXE만 교체하지 마세요.
3. 환경 설정의 '오른쪽 Alt를 한영키로 사용'이 켜져 있는지 확인합니다.
4. 서버를 시작하고 기존 RDP 또는 RDCMan으로 다시 접속합니다.
5. 원격 서피스에서 한국어 Microsoft IME를 선택하고 입력란을 클릭한 뒤 한영키를 누릅니다.
6. 옵션을 바꾼 경우 설정 저장 후 서버를 중지하고 다시 시작해야 적용됩니다.
7. 자동 시작을 사용했다면 새 프로그램의 환경 설정을 저장해 실행 경로를 갱신하세요.

검증과 남은 확인
- 옵션 ON: 오른쪽 Alt RDP 입력을 VK_HANGUL 누름/뗌으로 변환하는 경로를 검사했습니다.
- 옵션 OFF: 일반 오른쪽 Alt/AltGr 스캔 코드를 유지하는 경로를 검사했습니다.
- 반복 입력, 전경 키보드 배치가 바뀐 뒤의 키 뗌, 왼쪽 Alt/오른쪽 Ctrl/일반 문자, 기존 한영·한자키를 검사했습니다.
- 기존 설정 파일 로드, 새 옵션 저장, 암호화, 트레이 기능 및 GPU AVC420 연결 회귀 검사를 수행했습니다.
- 실제 사용자 Surface의 한국어 IME 전환·조합은 아직 확인하지 못했습니다.
- 계속 작동하지 않으면 한영키를 두세 번 누른 직후 로그를 저장하세요.
  INPUT_ALT가 없으면 해당 키가 오른쪽 Alt 형태로 서버에 도착했는지부터 확인해야 합니다.
  INPUT_IME의 injected=2는 Windows API가 입력을 받았다는 뜻이며 최종 IME 전환 성공을 보장하지는 않습니다.

기존 기능 안내
새 계측 해석
- AUDIO_BUFFER actual_ms: 실제 할당된 WASAPI 버퍼 용량. 이 값 자체가 청취 지연은 아닙니다.
- AUDIO_LATENCY server_age_ms: 패킷 캡처 시각부터 서버 전송 호출까지의 대략적인 시간.
  QPC 캡처 시각이 유효하지 않거나 미래를 가리키면 패킷을 읽은 시각으로 대신합니다.
  AUDIO_STATS timestamp_estimates는 해당 대체 횟수이며, 이때 서버 시간에는 읽기 전 대기가 포함되지 않습니다.
  GetTickCount64 기반이므로 짧은 구간은 0ms로 표시될 수 있습니다.
- client_hold_ms: 클라이언트 Wave Confirm 타임스탬프가 보고한 대기/재생 지연의 평균 추정값.
  confirmed=0일 때 0ms는 지연 없음이 아니라 아직 확인되지 않았다는 뜻입니다.
  일부 클라이언트가 같은 패킷을 두 번 확인하므로 패킷별 큰 값을 사용합니다.
- ack_elapsed_ms: 서버 송신부터 확인 수신까지. 클라이언트가 재생 시간을 미리 추정해 회신하면
  client_hold_ms보다 작을 수 있습니다. 이 두 값을 더해 전체 지연으로 해석하지 마세요.
- pending: 최근 약 2초간 전송한 패킷 중 아직 확인 응답을 받지 못한 수. 전체 오디오 대기열 크기는 아닙니다.
- 이 계측은 실제 스피커/블루투스 출력부터 귀까지의 시간을 직접 측정하지 않습니다.
- 화면에는 '소리: 서버 약 ...ms / 클라이언트 보고 ...ms' 또는 확인 대기를 표시합니다.
- 실제 사용 중인 원격 PC에서 고정 지연이 사라졌는지는 아직 검증하지 못했습니다.

이전 버전 기능 안내
업데이트 후 비교 방법
1. 기존 프로그램을 트레이 메뉴의 '종료 (서버도 종료)'로 완전히 종료합니다.
2. 새 ZIP 전체를 별도 폴더에 압축 해제하고 WinHomeDesk.exe를 실행합니다.
3. 자동 DirectX / 자동 AVC420 / GPU 우선 / 긴 변 1440px / 30FPS로 이전과 같은 동작을 비교하세요.
4. 서버를 시작하면 기존 주소·포트의 RDP 또는 RDCMan으로 다시 접속할 수 있습니다.
5. 끊기는 동작을 15초 이상 반복한 뒤 '로그 저장'을 누르세요.
   특히 ENCODER, GPU_DEVICE, INPUT, PERF_CAPTURE, PERF_PIPELINE, PERF_SEND, H264_STAGE 행이 진단에 사용됩니다.
6. 자동 시작을 사용 중이었다면 새 폴더에서 환경 설정을 다시 저장해 새 EXE 경로를 등록하세요.

새 계측 해석
- PERF_CAPTURE: 독립 캡처 FPS, 캡처·축소 시간, 최신 화면 제출 복사 시간입니다.
  pipeline=latest일 때 wait_ms와 changed_fps는 이전 파서 호환용 0이며 화면 변화량을 뜻하지 않습니다.
- PERF_PIPELINE: taken은 처리 대상으로 받은 최신 화면 수, changed는 실제 픽셀이 달라진 화면 수,
  replaced는 받기 전에 더 최신 화면으로 교체된 수입니다. snapshot_ms는 비교·복사 시간입니다.
  age_ms는 캡처 완료부터 전달 스레드가 화면을 꺼낼 때까지의 평균 시간입니다.
  delivery_wait_ms는 게시한 업데이트 한 번당 클라이언트 처리 완료를 기다린 평균 시간입니다.
  이 대기는 별도 전달 스레드에서 발생하며 캡처 스레드를 막지 않습니다.
- H264_STAGE(AVC420): convert_ms는 RGB→YUV 변환, diff_ms는 변경 영역 검출,
  codec_ms는 실제 코덱 호출(처음에는 초기화 포함)의 평균입니다.
  convert/diff의 분모는 calls, codec의 분모는 codec_calls라서 값들을 단순 합산하지 마세요.
- 새 화면이 없는 구간에는 화면 나이를 0ms 지연으로 해석하지 말고 '새 화면 없음' 상태로 봅니다.
- PERF_SEND는 서버가 보낸 프레임 계측이며 상대 PC의 실제 표시 FPS나 왕복 지연은 아닙니다.
- CPU가 계속 포화 상태이면 프레임 교체가 늘 수 있습니다. 버퍼를 늘리면 지연이 커지므로
  이번 버전은 대기 화면 수를 늘리는 대신 최신 화면을 선택합니다.

설치·업데이트
1. 기존 WinHomeDesk의 서버를 중지하고 완전히 종료합니다.
   0.1.7부터는 X 버튼이 트레이로 숨깁니다. 트레이 메뉴의 '종료 (서버도 종료)'를 사용하세요.
2. ZIP 전체를 새 폴더에 압축 해제합니다. EXE만 교체하지 마세요.
3. WinHomeDesk.exe를 실행합니다. 관리자 권한이나 RDPWrap은 필요하지 않습니다.
4. 연결 주소, 포트(기본 3390), 전용 암호, 전송 방식, 현재 화면 공유 확인란을 확인하고 서버를 시작합니다.
5. 다른 PC의 기존 .rdp 또는 RDCMan으로 접속합니다. 주소·포트가 같으면 기존 파일을 쓸 수 있습니다. H.264를 사용하려면 색상을 32비트로 설정하세요.
   사용자 이름은 surface, Domain은 빈칸, 암호는 현재 WinHomeDesk의 전용 암호입니다.

시스템 소리 전송 (0.1.9 추가)
1. 서피스의 WinHomeDesk에서 '시스템 소리 전송'을 선택하고 서버를 시작합니다. 기본값은 켜짐입니다.
   변경하려면 서버를 중지해야 합니다. 서버를 시작할 때 설정이 저장됩니다.
2. 접속 PC에서 새 '연결 파일 저장'으로 만든 .rdp 파일을 사용하세요.
   기존 .rdp 파일은 우클릭 > 편집 > 로컬 리소스 > 원격 오디오 설정에서
   원격 오디오 재생을 '이 컴퓨터에서 재생'으로 지정하고 저장한 뒤 다시 접속합니다.
3. RDCMan의 기존 서버는 Properties > Local Resources에서 Inherit from parent를 해제하고,
   Remote sound를 'Bring to this computer'로 선택한 뒤 연결을 끊었다가 다시 접속합니다.
   버전에 따라 항목 이름은 Audio redirection / Play on this computer처럼 표시될 수 있습니다.
   새 RDG는 로컬 재생(Client)·고음질(High)·마이크 전송 끄기를 포함합니다.
4. 서피스에서 영상이나 음악을 재생하고 접속 PC의 음량·음소거·출력 장치를 확인하세요.
   소리가 계속 없으면 WinHomeDesk의 소리 상태와 '로그 저장' 기록을 확인합니다.

소리 전송 방식과 범위
- Windows WASAPI loopback으로 서피스의 기본 재생 장치 소리를 수집해 RDP rdpsnd 채널로 보냅니다. 오디오 묶음은 10ms입니다.
- 44.1kHz / 스테레오 / 16비트 PCM, 오디오 페이로드 약 1.41Mbps입니다. 영상 전송량은 별도입니다.
- '소리 전송 중'은 서버가 오디오 데이터를 전달했다는 뜻입니다. 접속 PC의 실제 스피커 재생까지 보장하는 표시는 아닙니다.
- 이 방식은 서피스의 현지 소리를 자동으로 끄지 않습니다. 양쪽에서 들릴 수 있습니다.
- 기본 재생 장치를 바꾸면 감지 후 다시 캡처합니다. 특정 앱이 다른 출력 장치를 사용하면 기본 장치로 변경하세요.
- 출력 장치 오류는 재시도하며, 소리 캡처 실패만으로 화면 서버를 중지하지 않습니다.
- 마이크 입력 전송은 구현하지 않았습니다. 오디오 녹음 파일은 저장하지 않습니다.
- 인증이 완료되고 오디오 채널이 준비된 연결에만 소리를 보냅니다.
- 전송 큐를 제한하고 오래된 소리를 버려 지연이 계속 쌓이는 것을 줄입니다. 느린 연결에서는 소리가 끊길 수 있습니다.
- 진단 로그: AUDIO(캡처 상태), AUDIO_CHANNEL(협상 상태), AUDIO_SENT(서버 전달 프레임),
  AUDIO_STATS(frames·queued·dropped·peak). queued는 대기열 등록 수이고 실제 재생 횟수가 아닙니다.

전송 방식 선택 (서버 중지 후 변경)
- 자동 — H.264 AVC420 우선 (기본): Windows 내장 RDP도 사용하는 RDPEGFX/H.264 규격으로 화면을 전송합니다.
  스크롤·창 이동을 먼저 비교할 모드입니다. 색이 있는 작은 글자는 번질 수 있습니다.
- 글자 선명도 — H.264 AVC444 우선: 클라이언트 지원에 따라 AVC444v2/AVC444를 사용합니다.
  색상 정보를 더 보존하지만 무손실은 아니며 CPU 사용량이 더 높아질 수 있습니다. 미지원 시 AVC420/Planar로 전환합니다.
- GFX Planar: 영상 프레임의 RGB 색상 정보를 무손실로 압축합니다. 화면 축소 과정 자체는 별도입니다.
- 호환 비트맵: 기존 전송 방식을 직접 선택합니다.
- GFX는 지원하나 H.264를 지원하지 않는 클라이언트에는 GFX Planar를 사용합니다.
  GFX 미지원 클라이언트나 16/24비트 색상 연결에는 호환 비트맵을 사용합니다.
- '실제: H.264 AVC420'과 '사용 중: GPU H.264' 같은 표시가 현재 연결에서 실제로 전송한 코덱입니다.
  선택한 모드 이름만으로 H.264 연결 성공을 판단하지 마세요. 연결 종료 후에는 종료 상태를 표시합니다.
- AVC420는 Windows Media Foundation 하드웨어 인코더를 우선 사용합니다. 실패 시 OpenH264 CPU 인코더로 전환합니다.
- AVC444/v2는 CPU 인코더를 사용합니다. GPU를 선택해도 클라이언트와 협상한 실제 코덱에 따라 달라집니다.
- H.264 목표 전송률은 10 Mbps입니다. GPU는 CBR을 요청하고 CPU 기본값은 VBR입니다. 인코더 목표 프레임률은 선택한 20/30/45 FPS에 맞춥니다.
  GPU와 CPU는 같은 화질/압축률을 보장하지 않습니다. GPU 경로에서 전송량이 증가할 수 있습니다.
  실제 전송률·FPS는 화면 변화, 클라이언트 기능, CPU와 네트워크에 따라 다르며 고정값/상한 보장이 아닙니다.
- 비교 시작점: 자동 DirectX + 자동 AVC420 + GPU 우선 + 1440px + 30 FPS.
  CPU 압축 시간이 길면 1440px 또는 20 FPS로 낮춰 비교하세요.

RDCMan에서 H.264 사용
1. 기존 서버의 Properties > Remote Desktop에서 상속을 해제하고 Colors/Color depth를 32비트로 설정합니다.
2. 연결을 끊었다가 다시 연결한 뒤 WinHomeDesk의 실제 코덱 표시를 확인합니다.
3. 새 '연결 파일 저장'은 session bpp:i:32를 포함합니다.
4. 새 RDG 생성은 각 서버의 remoteDesktop/colorDepth=32를 포함합니다.
   기존 RDG를 그룹 관리에서 불러와 다른 이름으로 저장하면 주소·계정·그룹을 가져와 32비트로 재생성합니다.
   이 그룹 관리기는 게이트웨이 등 모든 RDCMan 설정을 보존하는 범용 RDG 편집기는 아닙니다.
5. 클라이언트 구성요소가 GFX/H.264를 지원하지 않으면 32비트라도 비트맵 또는 Planar로 연결될 수 있습니다.

DirectX 캡처
- 기본값은 '자동 — DirectX 우선 / 실패 시 GDI'입니다.
- Windows Desktop Duplication(DXGI)으로 기본 모니터를 캡처합니다.
- 화면을 축소할 때 D3D11 GPU 셰이더로 축소하고 선택한 RDP 그래픽 인코더로 넘깁니다. GPU 캡처·축소와 GPU/CPU H.264 인코딩은 별개 단계입니다.
- 화면에 새 프레임이 없으면 GPU 읽기와 화면 비교를 생략하고, 연결 요청에는 보관된 화면으로 응답합니다.
- 실행창 '사용 중: DirectX (DXGI)' 또는 '사용 중: GDI'를 확인하세요.
  로그의 'SurfaceDesk CAPTURE backend=dxgi'도 DirectX 활성화를 나타냅니다.
- DirectX 초기화 또는 실행 중 오류가 발생하면 해당 실행에서는 GDI로 전환합니다. 이유와 오류 코드를 로그에 남깁니다.
- 'GDI — 기존 캡처 방식'을 직접 선택해 비교할 수 있습니다. 캡처 방식 변경은 서버를 중지한 후 가능합니다.
- 현재 DirectX 경로는 회전하지 않은 기본 모니터를 대상으로 합니다. 세로/회전 출력이나 지원되지 않는 출력은 GDI로 전환합니다.
- DirectX 축소는 선형 보간을 사용하므로 기존 GDI 고품질 축소와 글자 경계의 모습이 조금 다를 수 있습니다.
- CPU 메모리 복사·색 변환·변경 영역 비교·전송 단계가 남아 있습니다. 따라서 캡처 외 단계가 병목이면 체감 향상이 제한될 수 있습니다.

트레이 실행
- X 또는 Alt+F4: 창만 숨깁니다. 이미 실행 중인 서버와 연결은 유지됩니다.
- 트레이 아이콘 두 번 클릭 또는 '창 열기': 실행창을 다시 엽니다.
- 트레이 메뉴에서 서버 시작·중지, 환경 설정, 완전 종료를 선택할 수 있습니다.
- '종료 (서버도 종료)': 프로그램과 서버를 모두 종료합니다.
- 트레이 아이콘은 작업 표시줄의 숨겨진 아이콘(^) 안에 있을 수 있습니다.
- 같은 Windows 사용자 세션에서 중복 실행하면 기존 창을 엽니다. 서버를 여러 개 중복 실행하지 않습니다.
- 절전 중 접속은 불가능합니다. 이번 버전은 Windows 절전 설정을 변경하지 않습니다.

Windows 로그인 자동 실행 (기본 꺼짐)
1. 프로그램을 계속 둘 폴더를 먼저 정합니다.
2. 실행창 오른쪽 위 '환경 설정'을 엽니다.
3. 'Windows 로그인 시 트레이에서 자동 실행'을 선택하고 '설정 저장'을 누릅니다.
   이 옵션만 켜면 프로그램만 실행되며 원격 서버는 자동으로 시작하지 않습니다.
4. 서버도 자동으로 시작하려면 실행창의 연결 주소·화질·FPS·캡처 방식·전송 방식·암호·화면 공유 동의를 확인한 다음,
   환경 설정에서 '로그인 시 원격 서버도 시작 (현재 설정·암호 저장)'도 선택하고 저장합니다.
5. 다음 Windows 로그인 시 트레이에서 실행되고, 서버 자동 시작을 선택했다면 저장한 설정으로 서버를 시작합니다.
   로그인 전 원격 접속을 제공하는 Windows 서비스는 아닙니다.

자동 시작 세부 동작
- 현재 사용자 HKCU\Software\Microsoft\Windows\CurrentVersion\Run의 SurfaceDesk 항목을 사용합니다.
- 프로그램을 시작하는 것만으로 자동 시작 항목을 등록하지 않습니다. 환경 설정에서 저장할 때만 변경합니다.
- 자동 실행을 해제하고 저장하면 해당 항목을 제거합니다. 다른 프로그램의 시작 항목은 변경하지 않습니다.
- 서버 자동 시작을 켤 때만 전용 암호를 Windows DPAPI(CurrentUser)로 암호화해 저장합니다.
  암호화된 설정 파일을 다른 서피스나 다른 Windows 계정으로 옮겨 사용하지 마세요.
- 서버 자동 시작을 해제하고 저장하면 설정 파일에서 암호를 제거합니다.
- 서버 자동 시작이 켜진 상태에서 새 설정으로 '서버 시작'을 누르면 다음 로그인의 설정·암호도 갱신됩니다.
- 설정 저장 위치: %LOCALAPPDATA%\SurfaceDesk\preferences.xml
- 로그인 시 저장한 IP가 준비될 때까지 최대 60초 대기합니다. IP가 바뀌었다면 다른 주소로 임의 전환하지 않고 알립니다.
  실행창에서 새 주소를 선택한 뒤 환경 설정을 다시 저장하세요.
- 프로그램 폴더를 옮긴 경우 새 위치에서 환경 설정을 다시 저장해야 시작 항목의 경로도 갱신됩니다.
- 잠금·UAC 보안 화면·해상도 변경으로 중지된 서버를 자동 재시작하지 않습니다. 창에서 확인 후 다시 시작하세요.
- 이 배포 파일을 만드는 과정에서는 사용자의 실제 Windows 자동 시작 항목을 등록하지 않았습니다.

성능 비교·로그
1. 같은 캡처 방식·화질·목표 FPS에서 자동 AVC420과 호환 비트맵을 각각 시험하세요.
2. WinHomeDesk 창을 최소화하거나 트레이에 숨긴 뒤 원격 PC에서 같은 문서를 15~20초 스크롤합니다.
3. 실행창을 열고 '로그 저장'으로 각 시험의 기록을 따로 저장합니다.
- 계측은 약 2초 단위입니다. 서버 전송 FPS는 상대 PC의 실제 표시 FPS가 아닙니다.
- DirectX 새 프레임 FPS는 정지 화면에서 0이 될 수 있습니다. 오류를 뜻하지 않습니다.
- 캡처·축소 평균: 실제 새 프레임을 얻은 호출의 시간 평균입니다.
- 비교·복사 시간은 0.2.0부터 PERF_PIPELINE의 snapshot_ms로 분리했습니다.
- 전달 단계 대기는 PERF_PIPELINE의 delivery_wait_ms입니다. 독립 캡처의 대기 시간이 아닙니다.
- 캡처/전송 통계는 독립된 구간이고 평균의 분모도 다릅니다. 시간을 단순히 합산하지 마세요.
- 전송 호출 시간은 암호화·프로토콜 처리·소켓 쓰기 대기를 포함할 수 있으며 ping이 아닙니다.
- 압축 영상 데이터 Mbps는 비트맵/Planar/H.264 압축 페이로드의 합입니다. 프로토콜 헤더·TLS·재전송량은 제외합니다. 실제 회선 사용량과 다릅니다.
- 최대 시간은 순간적인 끊김을 확인하는 데 도움이 됩니다. 일정 초과 횟수는 정확한 유실 프레임 수가 아닙니다.
- PERF_CAPTURE 행에 backend, idle_polls, poll_ms를 추가했습니다.
  idle_polls는 새 화면이 없었던 확인 횟수, poll_ms는 전체 캡처 확인 호출의 평균 시간입니다.
- 약 6초 이상 갱신되지 않은 수치는 마지막 측정 시점을 표시합니다.
- 장시간 실행 시 오래된 로그 일부를 정리합니다. 시험 직후 저장하세요.

RDCMan / RDP 파일
- RDCMan Server name: 서피스 IP, Connection Settings의 포트: 기본 3390.
- '연결 파일 저장'으로 .rdp를 만들 수 있습니다. 다른 PC에는 127.0.0.1 대신 서피스 내부 IP를 사용하세요.
- 'RDCMan 그룹 관리'에서 여러 서피스를 그룹별로 추가하고 .rdg로 저장할 수 있습니다.
- 'RDP 파일 추가'는 여러 .rdp의 주소·포트·사용자·Domain을 선택한 그룹에 추가합니다.
- RDG에는 암호를 넣지 않습니다. RDCMan에서 필요하면 Shift+Enter(Connect As) 또는 서버 속성으로 암호를 입력하세요.
- RDP의 암호 프롬프트 옵션, 게이트웨이, RemoteApp 등은 RDG 가져오기로 변환되지 않습니다.

현재 범위와 검증 한계
- Windows Home x64에서 현재 로그인한 사용자의 기본 화면을 공유하는 실험 버전입니다.
- 로그인 화면, 잠금/UAC 보안 화면, 사용자 전환, 해상도 변경을 넘나드는 상시 서비스는 지원하지 않습니다.
- 전용 암호 인증, 20/30/45FPS, 트레이·자동 시작, RDP 가져오기와 RDG 그룹 관리 기능을 유지합니다.
- Windows 내장 RDP와 같은 RDPEGFX/H.264 규격을 추가했습니다. Windows의 WDDM 원격 디스플레이 드라이버나 별도 로그인 세션을 구현한 것은 아닙니다.
- 실제 서피스 LAN에서 스크롤 성능이 얼마나 개선되는지는 아직 측정하지 않았습니다.
- 새 아이콘은 두 모니터와 연결 화살표를 그린 자체 디자인이며 Microsoft 공식 아이콘이 아닙니다.
- 개발 환경에서는 Desktop Duplication이 0x80070005 접근 거부를 반환했습니다. GDI 자동 전환과 RDP 접속을 검증했습니다.
- 별도 D3D11 하드웨어 시험에서 실제 공유 코드의 복사·축소, 픽셀 색상·방향·행 간격 검증을 통과했습니다.
- 서피스의 실제 DXGI 데스크톱 캡처와 성능, 실제 재부팅 후 자동 실행은 아직 검증하지 않았습니다.
- 상세 검사 기록은 같은 폴더의 검증결과.txt에 있습니다.
